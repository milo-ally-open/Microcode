# T3Code UI reference mapping

This is a pattern inventory from the current `pingdotgg/t3code` `main` sources inspected for the Microcode desktop slice. It records structure and interaction only. No T3Code code, names, icons, or visual assets are used in the implementation.

| T3Code source | Observed pattern | Microcode mapping |
| --- | --- | --- |
| [`ChatView.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/ChatView.tsx) | The chat route composes a message timeline, composer, panel controls, right-side content, and terminal drawer while keeping the active conversation visible. | `renderer/App.tsx` keeps a persistent conversation column and mounts the review and terminal surfaces alongside it. Panel toggles do not clear the transcript, selected diff, or terminal output. |
| [`Sidebar.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/Sidebar.tsx) and [`ui/sidebar.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/ui/sidebar.tsx) | Project/thread rows are grouped in a collapsible sidebar; rows expose keyboard interaction, active state, and overflow-safe labels. | `App.tsx` keeps conversations as child rows of their owning project. There is no top-level or recent-conversation list; only the active project's sessions are expanded. |
| [`chat/ChatComposer.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/ChatComposer.tsx) | The composer gathers text, attachments, model choice, and interaction controls in a stable footer area. | The Microcode composer stays below the timeline and sends text plus image data only through named bridge methods. Model and permission choices dispatch the existing runtime commands. |
| [`chat/ComposerPendingApprovalPanel.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/ComposerPendingApprovalPanel.tsx) and its [`ChatComposer` usage](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/ChatComposer.tsx) | A pending action is described by category and target, with a queue position when multiple requests are waiting; the action remains visible near the composer. | `ApprovalCard` presents the runtime request ID's category, description, safe input details, queue position, and only the runtime's `allow`, `allow_session`, and `deny` decisions. The card stays pending until a runtime resolution event arrives. |
| [`DiffPanel.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/DiffPanel.tsx) and the [`MessagesTimeline.tsx` changed-file summary](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/MessagesTimeline.tsx) | Changed paths select a focused diff while chat remains in the main view; changed-file information is scoped to the active workspace. | `ReviewPanel` lists `GitRepository.status()` changes and loads one scoped diff at a time. It does not stage, discard, or modify files. |
| [`ThreadTerminalDrawer.tsx`](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/ThreadTerminalDrawer.tsx) | Terminal content is a lower drawer that can be shown while retaining chat context. | The Microcode bottom panel renders an interactive xterm terminal backed by a real Bash PTY owned by the Bun desktop sidecar. Its explicit bridge supports create, input, resize, and close; it does not mirror Agent tool output. |

## Boundary decisions

- The current Microcode `ApplicationRuntime` contract is the source of truth for sessions, turns, model selection, permission decisions, and sequenced events.
- The desktop backend adapter remembers live permission requests so a renderer reload can reconstruct the approval cards from a desktop snapshot. Closing the backend closes the runtime, which resolves pending permissions as denied.
- The renderer can call only explicit preload methods. Project selection and image reads are native-dialog actions in Electron main; Git status/diff and runtime execution remain in the Bun sidecar.
- The current turn diff is a workspace Git view, not a multi-repository scanner. No files outside the selected project are searched for review data.
